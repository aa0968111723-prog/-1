# 隱私與權限說明

適用範圍：FinTracker（Android 應用程式 `com.fintracker.app`）與其內建的小財桌寵。
本文件同時作為上架 Google Play 時填寫 Data Safety 表單的依據。

---

## 1. 我們蒐集什麼資料

**預設情況下：沒有任何資料離開這台裝置。**

具體而言：

- 帳本（交易、預算、循環記帳、負債、目標、長期試算表、分類與支付方式偏好）
  全部存在 App 自己的本機儲存空間（WebView `localStorage`，key 為 `finance_*`）。
- 桌寵在 App 未開啟時記的帳，暫存在 App 私有的 SharedPreferences（outbox），
  下次開 App 時匯入帳本後即刪除。
- **沒有帳號、沒有登入、沒有雲端同步。**
- **沒有任何分析／統計 SDK**：沒有 Firebase Analytics、沒有 Crashlytics、沒有廣告 SDK、
  沒有第三方追蹤器。App 不會回報使用行為、當機資訊或裝置識別碼給我們或任何第三方。
- 沒有廣告，沒有 IDFA / GAID 之類的廣告識別碼。

唯一會產生對外網路連線的功能是**選用的 AI 金流推論**，見第 4 節。

**代價要一起講清楚**：因為沒有雲端備份，清除 App 資料、解除安裝或換手機都會讓帳本消失。
請定期使用 App 內的「資料備份」匯出 JSON 檔案自行保存。匯出的檔案由使用者自己掌管，
我們看不到也收不到。

## 2. 權限逐項說明

以下是 `AndroidManifest.xml` 中宣告的全部權限。沒有列在這裡的權限就是沒有宣告。

### `SYSTEM_ALERT_WINDOW` — 顯示在其他應用程式上層

- **為什麼需要**：小財桌寵是真正的系統 overlay（`WindowManager` +
  `TYPE_APPLICATION_OVERLAY`），才能浮在桌面與其他 App 之上；這是「看到就記帳」體驗的前提。
- **不給會怎樣**：桌寵無法啟動，App 會顯示「✕ 未允許」與重新開啟的入口。
  **FinTracker 本體（記帳、預算、報表、負債、目標、匯出）完全照常使用。**
  桌寵永遠不是必要依賴。
- **時機**：只有使用者主動在 🐣 桌寵分頁按「開啟桌寵」時才會請求，並且會先顯示自家說明再導向系統設定。
- **我們用它做什麼**：只畫一隻可拖曳的桌寵與它的對話泡泡。不截圖、不讀取畫面內容、
  不覆蓋其他 App 的輸入元件以誘導點擊。

### `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` — 前景服務

- **為什麼需要**：overlay 必須由一個活著的服務持有，否則 App 一離開前景桌寵就會消失。
  服務型別為 `specialUse`，並在 manifest 中宣告 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`：

  > `user-enabled persistent floating personal finance quick-entry companion overlay (draggable pet; tap opens quick expense entry)`

  這個字串就是我們向 Google Play 說明「為什麼不能用既有 FGS 型別」的依據：
  它既不是媒體播放、也不是定位或資料同步，而是使用者自己開啟的常駐互動 overlay。
- **不給會怎樣**：桌寵無法常駐，離開 App 就消失。
- **邊界**：服務只在使用者於前景按下「開啟桌寵」時啟動（避免
  `ForegroundServiceStartNotAllowedException`），沒有 WakeLock、沒有輪詢、
  螢幕關閉時停止動畫。使用者可從長按選單、通知列或 App 內三個入口關閉。

### `POST_NOTIFICATIONS` — 通知

- **為什麼需要**：前景服務依規定必須有常駐通知（「🐣 小財正在陪你記帳」），
  該通知同時提供兩個動作：**記一筆**（直接開啟快速記帳）與**暫停**。
  重新開機後若無法自動恢復桌寵，也會改用「🐣 小財想回來陪你」通知讓使用者一鍵恢復。
- **不給會怎樣**：桌寵仍可運作，但恢復通知與通知列的快捷動作不可用。
- **邊界**：不推播行銷訊息、不推播提醒或催記帳。通知只有上述服務性用途。

### 錄音 / 麥克風（語音記帳）

- **FinTracker 本身沒有宣告 `RECORD_AUDIO`。** 語音記帳是透過系統的語音辨識器
  （`RecognizerIntent.ACTION_RECOGNIZE_SPEECH`，語言設為 `zh-TW`）完成：
  錄音與辨識都發生在系統的語音辨識 App 的行程中，由它持有麥克風權限，
  回傳給我們的只有辨識後的文字字串。
- **時機**：**只有使用者在快速記帳畫面點下 🎙 按鈕的那一刻**，才會叫起系統辨識器，
  並且會出現系統自己的錄音介面。
- **明確聲明：沒有任何背景聆聽。** App 不會在背景錄音、不會持續監聽關鍵字、
  不會在使用者未主動點擊時開啟麥克風。桌寵浮在畫面上時並沒有在聽。
- 辨識回來的文字由本機的 `NativeQuickParser` 解析成金額與分類，**不會送到任何伺服器**。
- **不用會怎樣**：手動輸入金額與分類，功能完全不受影響。

### `USE_BIOMETRIC` — 生物辨識

- **為什麼需要**：選用的「App 鎖定」功能，用裝置的生物辨識或螢幕鎖定憑證擋住完整帳本。
- **預設**：關閉（`appLock: false`）。開啟後仍可選擇讓快速記帳免解鎖，
  以免鎖定破壞「兩秒記帳」的核心體驗。
- **邊界**：我們只呼叫系統的驗證結果（成功／失敗），**不接觸也不儲存任何生物特徵資料**。
  指紋與臉部資料由 Android 系統保管，App 看不到。

### `VIBRATE` — 震動

- **為什麼需要**：記帳成功、長按選單開啟等操作的觸覺回饋。
- **不給會怎樣**：只是沒有震動，功能完全正常。

### `RECEIVE_BOOT_COMPLETED` — 開機完成廣播

- **為什麼需要**：重新開機後，把**使用者原本已經開啟的**桌寵恢復回來。
- **邊界**：只有在使用者先前明確啟用桌寵的情況下才會恢復；沒開啟過就什麼都不做。
  部分機型限制開機自啟，此時會降級為一則可點擊的恢復通知，不使用任何規避手段。
- **不給會怎樣**：每次重開機需要手動再開一次桌寵。

### `INTERNET` — 網路

- **為什麼需要**：**只有**選用的 AI 金流推論會用到，它呼叫的是本 App 自己的伺服器端點
  （`/api/gemini/*`）。
- **不用會怎樣**：除了 AI 分析，其餘功能全部離線可用——包含桌寵、快速記帳、
  自然語言解析、預算與報表。飛航模式下記帳是必測項目（見
  `docs/REAL_DEVICE_TESTING.md` Flow C）。

## 3. 桌寵的隱私姿態（overlay 上會看到什麼）

桌寵浮在其他 App 之上，隨時可能被旁邊的人看到，所以預設值刻意保守：

- **隱私模式預設開啟**：`bubbleDisplay` 預設為 `'text'`，`showAmounts` 預設為 `false`。
  也就是說**預設不在畫面上顯示任何金額**。使用者要主動改設定才會顯示今日支出或預算進度。
- **對話泡泡永遠不顯示總資產、負債總額或帳戶餘額。** 這些數字沒有任何路徑可以傳到 overlay，
  不是靠設定擋住，是資料根本沒送過去。
- **推送到原生層的只有一個精簡的顯示狀態**（`PetDisplayState`）：
  心情（mood）、訊息字串（message）、連續記帳天數（streak）、今日筆數（todayCount）、
  等級（level）、是否允許顯示金額（showAmounts）、桌寵名稱（petName）。
  **沒有交易清單、沒有餘額、沒有分類明細、沒有負債或目標資料。**
- 財務狀態一律由 Web 端的 `petFinanceState.ts` 計算後推送，原生層只負責顯示，
  不重算也不保存財務邏輯。
- 訊息文字刻意設計為鼓勵性質，不做財務羞辱。

## 4. AI 功能

- **選用，且不在關鍵路徑上。** 快速記帳（含自然語言解析「午餐120」「捷運50悠遊卡」）
  **完全不呼叫 AI**，解析在裝置本機完成，離線可用。桌寵不會因為沒網路而失效。
- AI 金流推論會把使用者的財務摘要送到 **本 App 自己的伺服器端點**，由伺服器代為呼叫模型供應商。
- **API 金鑰只存在伺服器端環境變數，不會出現在 APK 或 JS bundle 裡。**
  前端一律走相對路徑 `/api/...`，沒有任何一行前端程式碼持有金鑰。
- **已移除的踩雷點**：`vite.config.ts` 原本有一個
  `define: { 'process.env.GEMINI_API_KEY': ... }`。當時 `src/` 底下沒有任何程式碼引用它，
  所以金鑰還沒被 inline 進 bundle——但只要有人寫下一行 `process.env.GEMINI_API_KEY`，
  真實金鑰就會被打包進 JS bundle，而那個 bundle 會原封不動進到 APK 裡。
  這個 define 已經刪掉（`vite.config.ts` 現在留有一行說明為什麼不能加回來）。
- **發版前必檢查**：`grep -r "GEMINI_API_KEY" dist/` 必須是空的。伺服器端的
  `server.ts` 使用該環境變數是正確的，它不會被打包進 App。
- 使用者若從未使用 AI 功能，App 不會產生任何對外連線。

## 5. 使用者可以做的事

| 想做什麼 | 怎麼做 |
|---|---|
| 完全不使用桌寵 | 不授予懸浮視窗權限即可；App 本體不受影響 |
| 暫時讓桌寵消失 | 通知列 → 暫停桌寵；或長按桌寵 → ⏸ 暫停（30 分鐘／1 小時／直到我重新開啟）。不動任何資料 |
| 關閉桌寵 | 長按桌寵 → ✕ 關閉；或暫停中的通知 → 關閉桌寵；或 App → 桌寵分頁 → 關閉桌寵 |
| 不讓畫面上出現金額 | 維持預設的隱私模式（桌寵分頁 → 泡泡顯示 = 文字） |
| 鎖住帳本 | 桌寵分頁 → App 鎖定（可選擇快速記帳是否免解鎖） |
| 帶走自己的資料 | 導覽列 → 資料備份 → 匯出 JSON |
| 刪除全部資料 | 系統設定 → 應用程式 → FinTracker → 儲存空間 → 清除資料（本機刪除即為永久刪除，我們手上沒有副本） |

## 6. Google Play Data Safety 表單預期填答

供上架時對照。若未來新增任何 SDK 或連線行為，本節必須同步更新。

**Does your app collect or share any of the required user data types?**
→ **No**（預設不蒐集、不分享任何使用者資料）

各資料類別的預期填答：

| 類別 | 蒐集 | 分享 | 說明 |
|---|---|---|---|
| 個人資訊（姓名、Email、身分證號） | 否 | 否 | 沒有帳號系統 |
| 財務資訊（交易、付款資訊） | **否（不離開裝置）** | 否 | 帳本僅存本機；Play 定義的 collect 指傳輸離開裝置，本 App 不傳輸 |
| 位置 | 否 | 否 | 未宣告任何位置權限 |
| 通訊錄／通訊內容 | 否 | 否 | 未宣告 |
| 音訊 | 否 | 否 | 未宣告 `RECORD_AUDIO`；語音由系統辨識器處理，App 只取得文字 |
| 相片／影片 | 否 | 否 | 未宣告 |
| 應用程式活動、App 內搜尋紀錄 | 否 | 否 | 無分析 SDK |
| 當機記錄、診斷資訊 | 否 | 否 | 無 Crashlytics 或同類 SDK；診斷只顯示在 App 內的桌寵分頁，不外傳 |
| 裝置或其他 ID | 否 | 否 | 不讀取廣告 ID 或裝置識別碼 |

其他欄位：

- **Is all user data encrypted in transit?**
  → 是（唯一的對外連線為 AI 功能，走 HTTPS）
- **Do you provide a way for users to request that their data be deleted?**
  → 是。資料僅存於裝置，使用者可自行清除 App 資料完成刪除；我們沒有伺服器端副本可刪。
- **Data collection is optional / required?**
  → 不適用（未蒐集）
- **Independent security review?**
  → 尚未進行，據實填答。

**特殊權限的額外說明**（Play Console 會針對這幾項要求說明）：

- `SYSTEM_ALERT_WINDOW`：核心功能為使用者主動啟用的桌面浮動記帳夥伴，非廣告、非誘導點擊，
  可隨時由使用者關閉。
- `FOREGROUND_SERVICE_SPECIAL_USE`：subtype 字串如第 2 節所列；用途為維持使用者已啟用的
  常駐 overlay，無法以既有 FGS 型別涵蓋。
- `RECEIVE_BOOT_COMPLETED`：僅用於恢復使用者先前已啟用的 overlay。
