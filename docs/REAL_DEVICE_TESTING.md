# 小財桌寵 — 實機測試協定

CI 只能做兩件事：跑單元測試、把 APK 組出來。
**Overlay 的存活、前景服務被不被殺、電池歸屬、手勢與 IME 的互動，全部是 OEM 相依的，只能在真機上驗。**

本文件是「怎麼跑這一輪測試、每一步的通過標準是什麼、要記錄什麼」的協定。
逐機型的勾選清單另見 `docs/DEVICE_TEST_CHECKLIST.md`；兩份配合使用，不要只跑其中一份。

安裝方式：GitHub Actions → 最新 CI run → Artifacts → `app-debug-apk`，或本機
`npm run android:sync && npx cap open android`。

---

## 1. 裝置矩陣

每一輪發版前，下列類別**各至少一台**。同一台機器可以同時滿足多列（例如一台 6.8" 的 One UI 15）。

| # | 類別 | 系統 | Android 版本 | 這一台特別要看什麼 |
|---|---|---|---|---|
| D1 | Pixel-like（原生） | AOSP / Pixel | 14 (API 34) | 基準行為；specialUse FGS subtype 是否被接受 |
| D2 | Pixel-like（原生） | AOSP / Pixel | 15 (API 35) | 背景 FGS 啟動限制、BOOT_COMPLETED 恢復路徑 |
| D3 | Pixel-like（原生） | AOSP / Pixel | 16 (API 36) | targetSdk 36；edge-to-edge insets（桌寵不進狀態列／手勢區） |
| D4 | Samsung | One UI | 14 或 15 | 省電模式、Game Booster、「使未使用的應用程式進入休眠」 |
| D5 | realme / OPPO | ColorOS / realme UI | 14 或 15 | 獨立的浮動視窗開關、背景管理殺服務 |
| D6 | Xiaomi | HyperOS / MIUI | 14 或 15 | 自啟動管理、鎖定最近工作、通知類別限制 |
| D7 | 小螢幕（~5.5"） | 任一 | 任一 | Quick Add 不捲動即可完成；IME 彈出後儲存鈕仍可見 |
| D8 | 大螢幕（~6.8"） | 任一 | 任一 | 單手拇指可及；桌寵預設位置不在死角 |

**版本覆蓋的最低要求**：14 / 15 / 16 三個版本都必須至少各被一台涵蓋。
如果手上湊不齊，用 Emulator 補 API 版本的差異（overlay 與 FGS 行為可測），
但 **OEM 的背景管理與電池策略不能用 Emulator 代替**，必須真機。

每一輪開始前先記錄：機型、Android 版本、OEM 版本號、build 的 commit SHA。

## 2. 端對端流程

每個流程都是一條完整的使用者動線。**任何一步不符合通過標準就記為 fail，不要「大概可以」。**

### Flow A — 首次安裝到第一筆帳

- [ ] A1 全新安裝（若曾裝過，先解除安裝以清掉 localStorage 與 SharedPreferences）
- [ ] A2 開啟 App → 切到 🐣 桌寵分頁 → 按「開啟桌寵」
- [ ] A3 自家 onboarding 說明先出現（**不可以**還沒解釋就跳系統設定頁）
- [ ] A4 確認後導向系統「顯示在其他應用程式上層」設定，允許後返回
- [ ] A5 返回 App 的當下桌寵立即出現，不需要再按一次按鈕
- [ ] A6 點桌寵一下 → Quick Add 在 1 秒內出現，金額欄位已 focus、數字鍵盤已彈出
- [ ] A7 輸入 `120` → 點「餐飲 🍱」→ 完成
- [ ] A8 桌寵播成功動畫並顯示成功訊息；成功訊息不會被眨眼等閒置動畫蓋掉
- [ ] A9 開啟 App → 收支明細出現 NT$ 120 / 餐飲那一筆
- [ ] A10 Dashboard 今日支出與 Budget 的餐飲用量同步反映這筆

**通過標準**：從點桌寵到記完帳 ≤ 5 秒，且交易在 App 內出現一次，金額、分類、日期（今天）皆正確。

### Flow B — App 被 swipe 掉之後記帳（最重要的一條）

- [ ] B1 從 Recent Apps 把 FinTracker 完全滑掉
- [ ] B2 確認桌寵仍在畫面上（overlay 不隨 task 消失）
- [ ] B3 點桌寵 → 記 `80` / 咖啡（或餐飲）→ 完成，看到成功提示
- [ ] B4 **不要**先開 App，先回桌面繞一下（開 Chrome、按 Home）
- [ ] B5 開啟 FinTracker
- [ ] B6 收支明細出現該筆 NT$ 80
- [ ] B7 把 App 再切到背景、再切回前景（觸發第二次 drain）

**通過標準**：帳本裡**只有一筆** NT$ 80，不重複；桌寵分頁的「待同步筆數」在匯入後歸 0。
重複出現兩筆即為嚴重缺陷（冪等匯入失效），必須附上 `FinancePetSync` 的 logcat。

### Flow C — 離線（飛航模式）

- [ ] C1 開啟飛航模式，確認完全無網路
- [ ] C2 點桌寵記一筆 → 成功
- [ ] C3 完全結束 App（swipe 掉）並重新開啟，仍維持飛航模式
- [ ] C4 交易存在且正確

**通過標準**：整條記帳路徑不需要任何網路。若任何一步出現載入轉圈或錯誤提示，
代表有東西偷偷打了網路，必須查出來（快速記帳不得呼叫 AI，見 `docs/PRIVACY_AND_PERMISSIONS.md`）。

### Flow D — 權限被撤銷

- [ ] D1 桌寵運作中，到系統設定關閉「顯示在其他應用程式上層」
- [ ] D2 服務安全停止：**不 crash、不出現 ANR、不留下殭屍通知**
- [ ] D3 開啟 App → 桌寵分頁 → 進階，顯示「懸浮視窗權限 ✕ 未允許」
- [ ] D4 畫面上有「重新開啟權限」按鈕，按下去能回到系統設定
- [ ] D5 重新允許後按「開啟桌寵」，桌寵回來，位置與設定沒有遺失
- [ ] D6 權限被關的整段期間，FinTracker 本體（記帳、預算、報表）完全正常可用

**通過標準**：桌寵永遠不是 App 的必要依賴。權限被拒等於少一個功能，不等於 App 壞掉。

### Flow E — 旋轉 / 分割畫面 / 折疊尺寸變化

- [ ] E1 桌寵運作中，portrait ↔ landscape 旋轉數次
- [ ] E2 桌寵按比例恢復位置，不跑出畫面、不疊到狀態列或手勢列
- [ ] E3 旋轉後點桌寵，Quick Add 正常開啟且可完成一筆
- [ ] E4 進入分割畫面（上下各一個 App），桌寵仍可點、Quick Add 仍能完成
- [ ] E5（折疊機）內外螢幕切換，桌寵位置合理、不消失
- [ ] E6 字體縮放調到 1.3 倍以上，Quick Add 不破版、按鈕不被裁切

**通過標準**：任何尺寸變化之後，桌寵都仍然「看得到、點得到、記得成」。

### Flow F — 螢幕關閉再開

- [ ] F1 桌寵運作中，按電源鍵關螢幕，等 2 分鐘
- [ ] F2 開螢幕解鎖 → 桌寵仍在，位置不變
- [ ] F3 桌寵狀態（心情／訊息）合理，沒有停在錯誤的狀態
- [ ] F4 **沒有失控動畫**：不會一直抖動、不會連續播放、不會停在動畫中間的怪姿勢
- [ ] F5 夜間（23:00–07:00）觀察一次，桌寵應進入 sleep 狀態

**通過標準**：螢幕關閉期間動畫應完全停止（服務監聽 `ACTION_SCREEN_OFF` / `ACTION_SCREEN_ON`）；
開螢幕後恢復正常，沒有補播積壓的動畫。

### Flow G — 重新開機

- [ ] G1 桌寵開啟狀態下重新開機
- [ ] G2 解鎖後等待最多 1 分鐘
- [ ] G3 桌寵自動恢復 **或** 出現「🐣 小財想回來陪你」通知
- [ ] G4 若走通知路徑，點「恢復」後桌寵確實回來
- [ ] G5 恢復後位置、設定與 outbox 內容都還在

**通過標準**：允許兩種結果之一（自動恢復／通知恢復），但**不允許第三種**：
什麼都沒有、使用者只能自己開 App 才發現桌寵不見了。
記錄該機型走的是哪一條路徑——這是 OEM 差異最大的一項。

## 3. 逐畫面（surface）檢查

桌寵運作中，依序切到下列畫面，每一個都確認：**桌寵存在、可點、Quick Add 可完成一筆、不遮擋該畫面的關鍵操作**。

| 畫面 | 存在 | 可點 | 特別注意 |
|---|---|---|---|
| Launcher / 桌面 | [ ] | [ ] | 不擋圖示與搜尋列 |
| Chrome | [ ] | [ ] | 網頁捲動時不誤觸桌寵 |
| LINE 或任一聊天 App | [ ] | [ ] | 不擋輸入框與送出鍵 |
| YouTube 全螢幕 | [ ] | [ ] | 維持 edge dock，不跳到畫面中央 |
| 相機 | [ ] | [ ] | **不得遮擋快門鍵**；必要時長按 → 暫停 30 分鐘 |
| 遊戲（任一全螢幕遊戲） | [ ] | [ ] | 不吃掉遊戲觸控；Game Booster 若殺掉服務要記錄 |
| 任一鍵盤開啟中的畫面 | [ ] | [ ] | 桌寵不擋主要輸入區與候選字列 |

若某個畫面上桌寵**應該**被系統隱藏（例如某些 OEM 的安全鍵盤或支付畫面），
那不是缺陷，但要記錄下來，因為它會影響「桌寵不見了」類型的客訴判讀。

## 4. 電池量測

### 方法

1. 充飽電，關閉飛航模式以外的變因（不要同時跑其他測試）。
2. 開啟桌寵，**不做任何互動**，讓它閒置 **8 小時**（含正常的螢幕關閉時間）。
3. 8 小時後到 系統設定 → 電池 → 用電量，記錄 FinTracker 的電池歸屬（百分比與背景時間）。
4. 同時記錄：螢幕開啟的總時間、期間是否有記帳、是否進過夜間 sleep。

### 預期結果

**可忽略不計。** 理由是設計上就沒有耗電來源：

- 沒有 WakeLock。
- 沒有輪詢（no polling loop）。
- 沒有永久動畫：閒置動畫是 8–20 秒觸發一次的單發短動畫，播完就停。
- 螢幕關閉時動畫**完全停止**（監聽 `ACTION_SCREEN_OFF`），開螢幕才恢復。
- 財務狀態只在 Web 端資料變動時推送一次（300ms debounce），不是定時推。

### 判讀

| 觀測值 | 判定 |
|---|---|
| < 1%（8 小時閒置） | 通過 |
| 1–3% | 可接受，但記錄機型與 OEM，比對其他機型是否一致 |
| > 3% | **視為缺陷**。抓 `adb shell dumpsys batterystats` 找出是誰在喚醒；重點看是否有非預期的 wakeup 或動畫沒停 |

## 5. OEM 背景管理

**先講清楚：各家 OEM 的背景管理行為不一樣，而且會隨系統更新改變。我們不對抗它。**

原則：

1. **App 必須能在被殺的情況下不掉資料。**
   服務被 OEM 終止是允許發生的事；資料遺失不是。Flow B 與 Flow G 就是在驗這件事。
2. **不做 `Build.MANUFACTURER` 分支。**
   程式碼裡不會出現「如果是 Xiaomi 就……」這種判斷。理由：偵測不可靠、會隨機型與 ROM 版本失效，
   而且會產生只有特定使用者才踩得到、我們永遠重現不了的路徑。
   針對 OEM 的建議**只出現在文件與說明文字裡**，不進入執行邏輯。
3. **不主動要求忽略電池最佳化。**
   不彈 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。使用者若想讓桌寵更穩定，請他自己去看該機型的
   系統設定（自啟動、背景管理、電池最佳化、鎖定最近工作），路徑以他手上那台機器的實際 OS 為準——
   **不要照抄網路教學的路徑寫進文件**，那些路徑經常已經過時。

測試時要記錄的是事實，不是解法：

- [ ] 服務在閒置多久後被殺（或整段測試都沒被殺）
- [ ] 被殺後常駐通知是消失還是留著
- [ ] 被殺後 outbox 裡未同步的資料是否完整（**這一項不通過就是嚴重缺陷**）
- [ ] 該機型是否有標準 overlay 權限之外的第二個浮動視窗開關（ColorOS 常見）
- [ ] 重開機後走的是自動恢復還是通知恢復（Flow G）

確認某機型會殺服務時，處理順序是：**先確保不 crash、資料不掉、可從通知恢復**，
之後才考慮在設定頁補上該機型的說明文字。不要為了讓服務活下去而加 hack。

## 6. 如何回報問題

一份能修的回報要有下列全部資訊。缺任何一項都可能導致無法重現而被擱置。

**1. 環境**
- 機型與 OEM 系統版本（例如 realme GT / realme UI 5.0）
- Android 版本與 API level（設定 → 關於手機）
- APK 來源與 commit SHA（CI artifact 的 run 編號即可）

**2. 桌寵狀態**（App → 🐣 桌寵分頁 → 進階，把這五個值抄下來）
- 懸浮視窗權限：已允許 / 未允許
- 通知權限：已允許 / 未允許
- 桌寵服務：Running / Stopped
- 待同步筆數
- 上次同步時間、位置（edge 與正規化座標）

**3. 重現步驟**
從哪個 Flow（A–G）的第幾步開始不對，預期看到什麼、實際看到什麼。
若與資料有關，請明確寫出「App 內看到幾筆、應該幾筆」。

**4. logcat**

原生層目前的 log tag 只有兩個：`FinancePetService`（服務／overlay 生命週期）與
`FinancePetSync`（outbox 寫入、讀回、損壞修復）。Web 端的匯入 log 前綴為 `[FinancePet.Sync]`。

```bash
# 只看桌寵相關（推薦，輸出最乾淨）
adb logcat -v time FinancePetService:V FinancePetSync:V *:S

# 連 WebView console 一起看（追 drain / 匯入問題時用）
adb logcat -v time | grep -E "FinancePet|chromium"

# crash 或 ANR
adb logcat -v time -b crash
```

回報崩潰時請附完整 stack trace，不要只貼最後一行。
回報「帳不見了」時，`FinancePetSync` 的完整輸出是必要的——
它會顯示 outbox 的 commit 是否成功、read-back 是否找得到那筆、payload 有沒有被判定為損壞而備份重建。

**5. 不要附的東西**
不要附帳本內容或備份 JSON（含真實金額）。回報只需要筆數與 id，不需要金額細節。
