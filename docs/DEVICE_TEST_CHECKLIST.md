# 小財桌寵 — 實機測試清單

Overlay 與電池策略在各 OEM 差異很大，發佈前請至少在下列機型類別各跑一輪。
（此清單供真人實機驗證；CI 只能驗證 build 與單元測試。）

## 測試矩陣

| 機型類別 | Android 版本 | 重點 |
|---|---|---|
| Pixel-like（原生 Android） | 14 / 15 / 16 | 基準行為 |
| Samsung（One UI） | 14 / 15 | Game Booster、省電模式對 FGS 的影響 |
| OPPO / realme（ColorOS / realme UI） | 14 / 15 | 浮動視窗權限、背景管理、電池管理（見下方注意事項） |
| Xiaomi（HyperOS / MIUI） | 14 / 15 | 自啟動管理、鎖定最近工作 |
| 小螢幕手機（~5.5"） | 任一 | Quick Add 不需捲動即可完成 |
| 大螢幕手機（~6.8"） | 任一 | 單手拇指可及性 |

## 核心流程（每台機器都要）

### Flow A — 首次安裝
1. 安裝 → 開啟 App → 🐣 桌寵分頁 → 開啟桌寵
2. Onboarding 四步驟顯示正常，導向系統設定後回來桌寵立即出現
3. 點桌寵 → 輸入 120 → 點 🍱 → 記下來 → 桌寵跳一下「記好啦！」
4. 收支明細出現該筆交易，Dashboard 與 Budget 同步更新

### Flow B — App 未開啟記帳
1. Recent Apps 把 FinTracker 完全 swipe 掉
2. 桌寵仍在 → 點桌寵 → 記 NT$120
3. 重新開啟 FinTracker → 交易存在、無 duplicate

### Flow C — 位置保存
1. 拖桌寵到左側中段 → 關閉 App → 重開機（或 force stop 後從通知恢復）
2. 桌寵恢復在大約相同位置（左側中段）

### Flow D — 權限撤銷
1. 系統設定關閉「顯示在其他應用程式上層」
2. 桌寵服務安全停止、不 crash；App 設定頁顯示「✕ 未允許」與重新開啟按鈕

### Flow E — 離線
1. 開飛航模式 → 點桌寵記一筆 → 成功
2. 重啟 App（仍離線）→ 交易存在

## 逐項檢查

### Overlay 持續性
- [ ] Home / Launcher 上桌寵存在
- [ ] Chrome 前景時存在
- [ ] LINE（或任一聊天 App）前景時存在
- [ ] YouTube 全螢幕：桌寵維持 edge dock，不跳到中央
- [ ] 相機開啟：不遮擋快門（必要時長按 → 暫停 30 分鐘）
- [ ] 鍵盤開啟：桌寵不擋主要輸入區
- [ ] 螢幕關閉再開：桌寵仍在
- [ ] 旋轉 portrait ↔ landscape：位置按比例恢復、不跑出畫面

### 手勢
- [ ] 單擊 → Quick Add（< 1 秒出現）
- [ ] 拖曳流暢、放手吸附最近邊緣（柔和動畫）
- [ ] 拖曳過程中不會誤觸發 Quick Add
- [ ] 長按 → 選單（支出/收入/語音/總覽/設定/暫停30分/關閉）
- [ ] 閒置後收邊（依設定 5s/15s），點一下彈回
- [ ] 拖曳中與 Quick Add 開啟中不收邊

### Quick Add
- [ ] 金額自動 focus + 數字鍵盤自動彈出
- [ ] IME 出現時儲存鈕仍可見（不被鍵盤蓋住）
- [ ] 快速模式：輸入 120 → 點 🍱 → 直接完成 + 復原列出現
- [ ] 復原列點「復原」→ 交易不會出現在 App
- [ ] 支付方式沿用上一筆
- [ ] 語音記帳「午餐一百二十塊」→ 解析出 120 / 餐飲，確認後儲存
- [ ] Dark mode 下配色正常
- [ ] 字體放大 (font scale 1.3+) 不破版

### 資料安全
- [ ] 同一筆 native 交易重複 drain 不產生 duplicate
- [ ] Native 記 120 餐飲、同時 Web 記 50 交通 → 兩筆都存在
- [ ] 記帳後立刻 force stop App → 重開 → 交易存在
- [ ] 匯出 JSON → 清除資料 → 匯入（取代）→ 資料完整

### 服務生命週期
- [ ] 通知常駐顯示「🐣 小財正在陪你記帳」+ 記一筆 / 暫停
- [ ] 通知「記一筆」直接開 Quick Add
- [ ] 重開機後桌寵自動恢復（或出現恢復通知）
- [ ] 系統回收後（開多個大型 App）桌寵可恢復、位置/設定/outbox 不遺失

## OPPO / realme 特別注意

ColorOS / realme UI 對懸浮視窗與背景服務管理較嚴格，實測時留意：
- 浮動視窗權限可能在系統設定中有獨立開關（除了標準 overlay 權限之外）
- 背景管理／電池管理可能在閒置後終止前景服務——驗證桌寵是否被殺、通知恢復是否可用
- 以實際 OS 行為為準記錄設定路徑，不要照抄網路教學

若確認特定機型會殺服務，先確保「不 crash、資料不掉、可從通知恢復」，
再考慮於設定頁加入該機型的說明（不主動要求忽略電池最佳化）。

## Android 版本重點

- **Android 14 (API 34)**：specialUse FGS 需宣告 subtype property（已宣告）；驗證通知權限拒絕時桌寵仍可用
- **Android 15 (API 35)**：背景 FGS 啟動需可見 overlay——驗證 BOOT_COMPLETED 恢復路徑與通知 fallback
- **Android 16 (API 36)**：targetSdk 36；驗證 edge-to-edge 下 insets 正確（桌寵不進 status bar / 手勢區）
